# boj-discord-bot

solved.ac 티어로 매일 연습 문제를 고르고, 목표별 학습과 풀이 확인을 제공하는 3인용 Discord 봇 프로젝트다. Rust로 구현하고 사용자별 JSON 파일을 사용한다.

## 3명 운영 시작

홈서버에서 새 코드를 받고 한 번에 빌드·설치한다. 기존 서비스가 설치돼 있어야 한다.

```sh
cd ~/boj-discord-bot
git pull --ff-only && sh scripts/deploy-server.sh
```

기존 설정, OAuth 로그인, 오늘 추천, 쉬기 상태를 보존한다. 설치 실패 시 이전 실행 파일 복구를 시도하며 백업 경로를 출력한다. 실행 상태 검사는 Discord 연결 성공을 대신하지 않으므로 `/version`과 아래 명령으로 최종 확인한다. `BOT_DATA_DIR`을 별도 경로로 설정했다면 감사 도구에 `--data 경로`를 전달한다.

각자 지정 채널에서 다음 순서로 시작한다. 설정·OAuth·추천·풀이 결과·진도는 Discord 사용자별로 저장한다.

1. `/setup handle:내핸들 count:2` → `/connect`에서 자기 계정 승인 → `/account`로 확인
2. `/settings delivery:dm reminder:21:00` → `/notify-test`로 개인 DM 수신 확인 (공개 알림은 `delivery:channel`)
3. `/curriculum track:cache` 또는 `/goal text:내목표` → 제안된 트랙 직접 선택
4. `/today` → 문제 풀이 → `/check` → `/status`
5. 어려우면 `/hint problem:1` → 제안 코드로 `/replace offer:코드`를 실행해 교체

기존 사용자는 설정을 다시 만들 필요 없이 `/settings`에서 원하는 알림 방식만 선택하면 된다. 기본값은 기존과 같은 지정 채널이다. 오늘 이미 알림을 보냈다면 방식을 변경해도 다시 독촉하지 않는다. DM 거부 시 공개 채널로 전환하지 않는다. `/notify-test`는 쉬는 중에도 사용자가 요청해서 보내는 테스트이며 자동 알림 기록을 변경하지 않는다.

`/skip days:1`은 추천과 독촉을 중단한다. 기간 종료 시 선택한 방식으로 재개 여부를 한 번 묻고, `/resume` 전에는 계속 정지한다. 과거 문제를 소급 배정하지 않는다.

### 구현 및 검증 상태

초기 설정, OAuth, 추천, 실제 풀이 조회, 개인별 DM/채널 알림, 스킵·재개 질문, 커리큘럼 자동 진행, agy 도움과 추천 슬롯 교체를 연결했다. 자동 테스트는 모의 API와 임시 사용자 저장소를 사용한다. 실제 세 사람의 로그인, DM 도착, 실토큰 만료 후 갱신, 모델 실행 중 메모리 측정은 홈서버에서 확인해야 한다.

```sh
sudo python3 scripts/audit-runtime.py
```

이 도구는 비밀 값 없이 설정 사용자·서로 다른 연결 계정 수, 풀이 권한·갱신 수단 유무와 서비스 메모리를 출력한다. 저장된 상태를 읽는 검사이며 API 인증 성공을 뜻하지 않는다. 자세한 운영 확인은 [3명 운영 확인](deploy/OPERATIONS.md)을 따른다.

### Discord 연결 확인

Discord 명령과 사용자별 설정 저장을 연결했다. 프로젝트 폴더에서 다음과 같이 실행한다.

1. `.env.example`을 `.env`로 복사한다. `.env`는 Git에서 제외된다.
2. `DISCORD_BOT_TOKEN`에 Bot Token을, `DISCORD_GUILD_ID`에 초대한 테스트 서버 ID를, `DISCORD_CHANNEL_ID`에 사용할 채널 ID를 넣는다. Application ID와 채널 ID는 예시에 설정되어 있다.
3. `sh scripts/run.sh`로 실행하고 테스트 서버에서 `/ping`을 입력한다. Cargo가 PATH에 없어도 기본 Rust 설치 경로에서 찾는다. 첫 실행에는 의존성 다운로드와 빌드가 필요하다.

서버 ID는 Discord 설정 → 고급 → 개발자 모드를 켠 뒤 서버 아이콘을 우클릭해 복사한다.
토큰은 채팅이나 저장소에 올리지 않는다. 별도의 privileged intent 설정은 필요 없다.
명령은 지정한 서버에만 등록하며 지정한 채널에서만 응답한다. 응답은 명령을 실행한 사용자에게만 보인다. 다른 방의 가시성과 명령 표시 제한은 Discord 채널 권한 및 서버 연동 설정에서 별도로 설정한다. 종료는 Ctrl+C다.
`/help`에서 사용법과 연결 상태를 볼 수 있다. `/setup handle:핸들 count:3`은 solved.ac 프로필 조회 후 초기 설정을 저장한다. 서버에 `SOLVED_AC_CLIENT_ID`와 `SOLVED_AC_CLIENT_SECRET`을 모두 설정해야 한다.

처음 사용하는 사람은 `/start`로 시작한다. 미설정 사용자에게 핸들 확인·초기 설정을 안내하고, 설정된 사용자에게 `/today`, 쉬는 사용자에게 `/resume`을 안내한다. 현재 추천 이용에 OAuth는 필요 없다.

`/settings`는 설정 조회, `count`, `reminder`, `delivery`, `handle` 옵션은 설정 변경이다. `goal`은 단독 옵션으로 지원 트랙을 선택하거나 자유 목표를 AI에 제안받는다. `/skip days:1`, `/resume`은 학습 정지 상태를 저장·해제한다. `/curriculum track:cache`는 트랙을 저장하고 현재 단계를 보여준다. 각 사용자는 자신의 데이터만 변경한다. 데이터는 `BOT_DATA_DIR` (기본 `data`) 아래에 저장한다.

`SOLVED_AC_REDIRECT_URI`가 설정돼 있으면 `127.0.0.1:8787/oauth/callback`에서 OAuth 콜백을 받는다. `/connect`는 본인에게만 보이는 인증 링크를 만들고 `/account`는 저장된 연결 계정을 보여준다. HTTPS reverse proxy로 콜백만 연결하고 Backstage에 동일한 Redirect URI를 등록해야 한다. 콜백 URL의 쿼리는 인증 코드가 있으므로 프록시 접근 로그에서 기록하지 않는다. 링크는 10분 동안 유효하며 재시작 시 다시 생성해야 한다.

`/today`는 문제 목록을 최대 5페이지 조회하고 현재 티어 → 한 단계 아래 → 한 단계 위 순으로 후보를 고른다. 커리큘럼을 선택했다면 해당 단계 태그로 제한한다. 같은 날에는 저장된 추천을 재사용한다. 한국 시간 자정에 새 추천을 만들며 스킵 중에는 차단한다. 신규 추천 때 프로필 티어를 다시 조회한다. 후보가 부족하면 부족분을 표시한다. 조회 범위 밖 문제는 탐색하지 않으며, 날짜가 바뀌어도 같은 문제가 다시 나올 수 있다.

계정 미연결 사용자는 **풀이 여부 미확인 추천**을 받는다. OAuth 계정이 연결돼 있으면 새 추천 생성 시 저장된 핸들·토큰 소유자의 고정 계정 ID를 대조한 뒤 사용자 토큰으로 상세를 조회한다. `solved`는 제외하고 `partial` 또는 `tried`로 미완료 상태가 확인된 문제만 추천한다. null·상태 누락·새로운 상태 값도 제외하므로 충분한 후보를 찾지 못할 수 있다. 연결 계정의 인증 갱신·권한 확인 실패 시 풀이 미확인 추천으로 몰래 전환하지 않는다. 사용자별 OAuth 응답의 실검증은 별도로 필요하다.

추천 파일 `users/<id>/recommendations/<날짜>.json`의 `verified_account_id`가 계정 ID를 기록한다. 기존 파일에 이 필드가 없으면 풀이 미확인 추천으로 읽는다. 같은 날에는 기존 추천과 순서를 보존하며 계정 연결 이후에도 이미 저장된 추천을 교체하지 않는다. 스킵 중에는 OAuth·문제 조회 전에 차단한다. 미해결 과제나 커리큘럼 완료 실적으로 집계하지 않는다. `/check`로 현재 풀이 상태를 다시 조회할 수 있다. 연결 계정은 알림 시각 이후 풀이를 자동 확인한다. 개인별 알림 방식은 `/settings delivery:dm|channel`로 선택한다. AI 도움은 별도 agy 서비스 설치 후 사용한다. `/setup`은 프로필 설정이며 OAuth 계정 소유 인증을 대신하지 않는다.

### OAuth 계정의 실제 풀이 조회

`/connect` → 인증 → `/account`로 확인한 뒤 `/today` → `/check`를 실행한다. 봇이 저장된 OAuth 토큰을 갱신하고, 오늘 추천의 핸들·연결 계정·현재 토큰 소유자의 고정 계정 ID가 일치하는지 확인한다. 다른 계정이면 문제별 조회와 저장을 중단한다.

- 명시적인 `userStatus=solved`만 해결 확인, `partial`과 `tried`는 미완료 확인으로 표시한다. null·필드 누락·새로운 상태 값은 확인 대기이며 미완료로 단정하지 않는다. HTTP 오류도 확인 대기로 처리한다. 권한 오류·요청 제한·연결 오류가 나면 남은 호출을 중단한다.
- 결과는 `users/<id>/verifications/<날짜>.json`에 계정 ID·조회 시각과 함께 저장한다. `/status`는 직접 체크와 저장된 API 조회 결과를 함께 표시하며, `/check`는 다시 조회한다. 이전 해결 확인 이력은 일시 오류가 나도 보존하되 이번 조회 상태와 구분한다.
- solved.ac에 반영된 해당 계정의 해결 상태 기준이다. 오늘 새로 제출했음을 증명하지 않으며 API 반영 지연이 있을 수 있다. 개별 `subId`도 조회에 유지한다.
- `/done` 체크와 실제 풀이 조회는 별도다. 배정 시 계정 ID와 트랙·단계를 저장한 새 추천만 실제 해결 결과를 커리큘럼 실적으로 누적한다. 고유 문제 수가 단계 기준에 도달하면 다음 단계로 한 번 진행하며, 재조회·재시작으로 중복 집계하지 않는다. 목표를 변경해도 당일 추천의 저장된 단계에만 실적을 반영한다. 과거 추천처럼 단계 또는 배정 당시 미완료 증명이 없는 기록에는 소급 적용하지 않는다.
- 자동 테스트는 대체 응답으로 검증했다. 실제 OAuth 계정의 상세 `userStatus` 응답과 최종 `/check` 동작은 홈서버에서 검증해야 한다.

### 직접 완료 체크와 채널 알림

- `/done`: 오늘 추천 전체를 직접 완료 체크한다. `/done problem:1`은 오늘 추천의 1번만 체크한다. 같은 체크를 반복해도 중복 집계하지 않는다.
- `/done undo:true`: 오늘 전체 체크 취소. `/done problem:1 undo:true`는 1번만 취소한다. `/status`로 오늘의 체크 현황을 확인한다.
- `/settings reminder:21:00`: 개인 알림 시각. 기본은 한국 시간 21:00이다. 봇이 60초마다 대상자를 확인한다. 오늘 추천을 받은 연결 계정은 토큰을 갱신하고 계정 소유를 대조한 뒤 실제 풀이 상태를 조회한다. 모두 해결했거나 한 문제라도 확인 대기이면 알림을 보내지 않는다. 모두 상태가 확인됐고 미완료가 남으면 해당 문제 링크만 보낸다. 미연결 계정은 기존 `/done` 체크 기준이다. 스킵·재개 대기·오늘 추천 없음은 조회 전에 제외한다.
- 실제 풀이 조회 결과는 `/status`에도 반영한다. 같은 계정·같은 당일 문제를 모두 해결했다고 확인한 결과는 재사용한다. 부분 조회 결과는 발송 직전 최대 2분 동안 재사용한다. 상태 미확정·API 오류가 포함된 결과는 5분간 기다린 후 재확인한다. 연결 계정의 인증·API 실패를 수동 체크 알림으로 바꾸지 않는다.
- 미연결 계정 메시지는 ‘완료 체크가 없다’, 연결 계정 메시지는 ‘solved.ac 조회 기준 미완료’로 구분한다. 직접 체크를 실제 해결로 집계하거나 커리큘럼 실적으로 반영하지 않는다. 상세 결과는 본인 명령 응답에서 보고, 알림은 개인이 선택한 DM 또는 지정 채널로 전달된다. 사용자 멘션만 허용하며 역할·everyone 멘션은 허용하지 않는다. 긴 미완료 목록은 파일로 첨부하므로 Attach Files 권한도 필요할 수 있다.
- 체크는 `users/<id>/checkins/<날짜>.json`, 발송 시도는 `users/<id>/checkin-reminders/<채널>/<날짜>.json`에 저장한다. 기존 수동 알림과 자동 조회 알림이 같은 발송 기록을 공유하므로 업데이트 당일에도 중복을 막는다. 조회가 보류되면 발송 시도를 기록하지 않는다. 발송 직전 시도를 저장하고, 재확인에서 완료·보류·스킵으로 바뀌어 실제 전송하지 않았으면 해제한다. 명확한 Discord 거부(4xx)만 재시도하며 네트워크 오류·5xx 등 결과 미확정은 중복 방지를 위해 재발송하지 않는다. 발송 직전 종료되면 알림을 한 번 놓칠 수 있다.
- 한국 시간 자정에 체크 날짜가 바뀐다. 전날 추천이나 미체크 알림을 다음 날로 넘기지 않는다. 매일 `/today`로 추천받아 참여한다. 봇 재시작 시 이미 알림 시각이 지난 경우 60초 이내에 미체크 알림이 나올 수 있다.

수동 체크 명령에는 별도 토큰이 필요 없다. 채널 알림에는 봇의 해당 채널 보기·메시지 보내기 권한이 필요하다. 알림 발송 여부는 서버 로그와 운영 채널에서 별도로 검증한다.

홈서버에서 확인한 목록 응답은 `total`, `page`, `pageSize`, `problems`이며 문제 항목은 `problemId`, `subId`, `level`, `titles`, `tags`를 제공한다. 목록에는 `ojLinks`가 없으므로 조건에 맞는 후보를 고른 뒤 상세 API를 조회해 `ojLinks[].url`을 가져온다. 상세 조회는 미연결 계정의 경우 요청 문제 수의 두 배(최대 20회), 연결 계정의 경우 해결·상태 미확정 후보를 건너뛰기 위해 최대 30회로 제한한다. 실제 응답 구조와 링크 예시를 자동 테스트에 반영했다. 제 실행 환경에서는 외부 API 직접 호출을 검증하지 못했고 계정별 추천 필터의 운영 확인은 별도다. 링크를 읽지 못하면 임의의 BOJ 주소를 만들지 않고 실패 안내를 한다. 운영에서 아래 진단을 실행하면 비밀 값 없이 HTTP 상태와 응답 필드 이름을 확인할 수 있다.

```sh
sudo python3 scripts/check-solved-ac.py
```

다음 명령으로 로컬 검증을 실행한다.

```sh
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo fmt --check
```

## AI 서비스

### agy AI 학습 도움

`/goal text:LRU와 LFU를 배우고 싶어요`는 지원 트랙을 제안하고 사용자가 `/curriculum track:...`으로 확인할 때 적용한다. `/hint problem:1`은 오늘 추천의 제목·태그로 선수 개념과 더 쉬운 연습 후보를 안내한다. 후보는 연결 계정에서 미완료가 확인되고 원문제보다 쉬우며 관련 태그·저장된 단계 조건을 만족하는 문제만 모델에 전달한다. 오늘 추천에 포함된 문제는 후보에서 제외한다. 모델이 반환한 트랙·후보 ID와 출력 길이를 Rust에서 검증한다. 실패 시 직접 트랙 선택 또는 태그·검증된 후보 안내를 제공한다. 힌트 자체는 읽기 전용이다. `/replace offer:코드`를 실행하면 계정·날짜·슬롯·원문제·두 문제의 현재 풀이 상태·난이도·관련 태그·저장된 단계 조건을 다시 확인해 원자적으로 교체한다. 제안은 30분간 유효하고 다른 교체 후에는 만료된다. 이미 해결했거나 상태 미확정이면 보류한다. 기존 당일 알림 발송 기록과 단계는 유지하며, 교체 전 풀이 조회 결과는 현재 결과로 재사용하지 않는다.

AI 실행은 별도 `bojai` 계정의 Unix socket 서비스가 담당한다. 도구 전체 deny, strict 권한, sandbox, 단일 동시 호출, 시간·출력 제한을 적용한다. 봇의 비밀 값과 사용자 JSON에 접근하지 못하도록 systemd와 파일 권한을 분리한다. 프롬프트에는 목표 또는 제목·태그·후보 ID만 포함한다. 설정·실계정 로그인·실제 모델 호출·실제 제한 작동·메모리 검증은 [AI 서비스 설치 안내](deploy/AGY.md)를 따른다. `rojojun` 계정의 기존 로그인과 서비스 계정의 로그인은 별개다.

Debian 13 x86_64 홈서버의 바이너리 상시 실행은 [systemd 배포 안내](deploy/README.md)를 따른다.

운영 검증은 [3명 운영 확인](deploy/OPERATIONS.md)에 모았다. 실제 사용자의 승인과 문제 풀이·DM 수신은 각 계정에서 확인한다.

자격 증명과 사용자별 실행 데이터는 저장소 밖에서 관리한다. FSD 요구사항과 승인 스펙은 `requirements/`, `specs/`에 있다.
